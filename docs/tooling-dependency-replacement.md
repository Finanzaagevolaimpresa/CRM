# Tooling dependency replacement (R106)

This candidate removes all installed paths to `braces`, `micromatch`, and
`chokidar`. The baseline is main commit
`85fa76d3d1c110da44c892859a70f9151b79cb7f`. The runtime dependency declarations
and the versions of its 95 runtime packages are unchanged. No Prisma schema,
migration, application permission, provider mode, or production configuration
is changed.

## Two dependency roots

Tailwind 3.4.19 introduces three paths through micromatch, chokidar, and its
nested fast-glob. It is replaced with Tailwind 4.3.3 and
`@tailwindcss/postcss` 4.3.3. The fourth path starts in
`@next/eslint-plugin-next` 16.3.8. Only that plugin's fast-glob is replaced with
the published `tinyglobby` 0.2.17 package using a scoped npm override.

The lockfile is generated by npm. The alias retains `name: tinyglobby`, the
official registry tarball URL, and its integrity, rather than disguising a
patched copy of the vulnerable package. All 472 lock entries, representing 463
distinct package/version coordinates, remain in the security inventory.

## Bound the Next replacement to its actual consumer

tinyglobby is **not** a general substitute for fast-glob's directory API. The
qualified CRM configuration uses Next's default project root and does not enter
the custom-root glob branch.

`scripts/next-glob-guard.mjs` checks the exact Next plugin and replacement
versions, the scoped manifest override, all fast-glob importers in the plugin,
and the SHA256 of `utils/get-root-dirs.js`. It rejects an imported or effective
`settings.next.rootDir`. The guard wraps the original Next rule inside
`eslint.config.mjs`, so it also runs with direct ESLint and editor integration;
it is not dependent on an npm-script preamble. The canonical zero-warning lint
command is retained.

Changing Next, its consumer source, the replacement, or the project root
configuration requires requalification. The original rule is still executed.
Real ESLint counterproofs check four custom-root forms, a changed consumer,
and an invalid internal link to a synthetic Pages route. An App Router link
was not a valid positive counterexample for that unchanged upstream rule.

## Preserve existing CSS semantics

The previous static preflight and RGB palette are retained with upstream MIT
provenance. No Tailwind compiler or brace parser is vendored. Sources and
PostCSS are explicit in both the application and the mobile fixture; Docker
build contexts include the palette file.

Utility-only substitutions preserve the old small shadow, transparent outline,
sRGB gradient, following-visible-sibling spacing, and divider semantics.
`crm-space-y-*` and `crm-divide-*` intentionally retain the previous handling
of hidden and inline children. Global defaults are assigned to CSS layers so
focus classes keep their original precedence. The zero-width white ring offset
is retained because Firefox paints rounded corners differently when that
shadow becomes transparent.

The CSS qualification compiles the immutable baseline with its own installed
Tailwind 3 toolchain and the candidate with Tailwind 4. It compares computed
geometry and styles plus screenshot pixels in Chromium, Firefox, and WebKit at
390, 767, 768, and 1280 pixels. Focus transitions finish before sampling.
Equivalent CSS Color 4 serializations are normalized to rendered sRGB bytes;
the independent screenshot comparison retains its original threshold (zero
pixels differing by more than four channel levels). Before/after CSS, PNGs,
differences, and hashes are retained as synthetic CI artifacts for 30 days.

The existing mobile fixture separately exercises real navigation, permission
filtered counters, reduced motion, accessible final values, and incremental
CSS rebuilding after a synthetic source-file change and restoration.

## Keep both audit paths fail-closed

The inventory parser has a declared compatibility change. It identifies npm
aliases by the genuine package name and checks that name/version, canonical
registry URL, and integrity metadata agree. Bundled entries are admitted only
as explicitly declared direct children of a verified registry bundle. Missing,
orphaned, renamed, linked, or externally resolved entries remain rejected.
Bundled children are counted and scanned, not excluded.

The canonical npm 11.16.0 runtime and complete audits retain their low threshold.
OSV 2.5.1 retains its pinned binary checksum, empty ignore configuration,
complete-inventory comparison, and original fallback conditions. An integrity
string check is not a substitute for npm's byte verification during a clean
install.

`scripts/qualify-lock-inventory.ts` also runs the real pinned OSV scan directly
against the candidate lock. A separate temporary fixture has npm generate a
lock containing `innocent-alias: npm:braces@3.0.3`; no vulnerable code is
installed or executed. The normal npm gate must reject its complete audit and
OSV must report actual findings. Network, inventory, or scanner failures do not
count as successful counterproofs. The fixture is outside `node_modules`, which
the source extractor excludes.

## Limits and adoption

Tailwind 4 requires Chrome/Edge 111+, Safari 16.4+, and Firefox 128+. The earlier
Next support floor includes Firefox 111–127; that range is no longer covered.
Current browser-engine tests do not establish historical minimum-version
support or identify the browsers actually used by CRM operators. This is an
explicit adoption consideration, not an inferred production qualification.

The candidate must have complete green CI and an independent review of the
exact final HEAD, including this inventory change and the scoped lint guard.
Earlier failed runs and later fixes remain distinguishable. Existing guarded
database test skips must not be counted as passes. Results from another HEAD
do not transfer automatically.

No merge, deployment, data write, or provider activation is part of this PR.
Before adoption, rollback is simply leaving the baseline in use. Any later
repository revert or production rollback requires its own approved procedure;
returning to Tailwind 3 also restores the known dependency-audit blocker.
