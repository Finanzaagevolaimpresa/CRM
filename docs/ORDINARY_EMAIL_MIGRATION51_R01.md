# Ordinary email — Migration51 and compatible restart

The additive migration is `20261017120000_ordinary_email_v1`. It introduces the eleven previously isolated ordinary-email tables into Prisma's migration chain. Baseline: PR191 merge `57b265e9829b9ccd9ffe86314db9ef7071d1c2e7`, tree `d95fe672b5d75db112e03b52b1e5172175a8b55d`, fifty finished migrations. The first fifty migration files and their checksums remain immutable. Exact schema/DDL hashes are in `scripts/ordinary-email/schema-binding.json`.

The SQL is a single transaction, with a five-second lock timeout and a thirty-second statement timeout. It requires exactly the qualified fifty-migration baseline and no existing OrdinaryEmail tables. It creates no authority, channel, stream, credentials, cursor or other bootstrap data. All ordinary email tables start empty; the runtime remains closed until separately bound and qualified.

The historical SQL under scripts/ordinary-email remains synthetic-only and must never be used as the production migration. The new migration preserves its constraints, restrictive foreign keys, unique blocking attempts, immutable receipts, cursor compare-and-swap and conflict evidence. Prisma exposes relations without removing these database controls.

CI first rejects the migration on schema49, then proves failure atomicity on schema50 by injecting an error before COMMIT. It checks that all eleven tables and the new functions rolled back. The actual Prisma deployment then reaches schema51, preserves the exact prefix50 ledger and creates eleven empty tables. Replay must fail. Prisma foreign-key parity includes all twenty-one new relations. The native email database/browser tests use this migration, not an alternative test DDL.

The release image qualification preserves populated synthetic histories for RESERVED, CLAIMED, UNCERTAIN and ACCEPTED attempts; decisions, claims, outcomes; inbound streams at cursor version2; batches, source items, associations and conflicts. The authority, transport channel and stream in this retention fixture are disabled. This fixture proves persistence across exact-image restart, not authorization or delivery to a provider; the separate native tests cover those paths. The before/restart/resume fingerprints include all eleven tables. PostgreSQL and document storage are not restarted or restored by this test.

Recovery after deployment uses the exact qualified schema51 image or a separately reviewed compatible forward correction. No downmigration, table removal, reset of cursors, retry of uncertain delivery, or return to PR190/PR191 application code is admitted after email state exists. An expired/uncertain claim remains visible and blocks automatic resend.

Production requires an exact merged commit/tree/image, schema50 preflight with current registry/session/perimeter health, compatible recovery evidence, and the exact migration target and authority. A migration or application cutover does not itself enroll Antonio, enable SMTP, initialize INBOX, or start a timer. Those operations require their concrete personal/channel binding and initial temporal scope. No new backup or transfer authority is inferred from earlier release exceptions.
